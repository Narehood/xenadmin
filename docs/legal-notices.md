# Binary redistribution notices

The repository's [LICENSE](../LICENSE) contains the XCP-ng Project, Cloud
Software Group and Citrix copyright notices, redistribution conditions and
disclaimer. Both BSD binary-redistribution clauses require that complete text
in documentation or other materials supplied with a distribution. A short
copyright label or a link to a website is insufficient on its own.

Both clients now include the unchanged license and
[THIRD-PARTY-NOTICES.txt](../THIRD-PARTY-NOTICES.txt) as embedded resources in
`XenCenterLib`. The shell displays them offline in Settings → About, with
selectable, read-only text. WinForms displays them through About → View Legal
Notices. Ordinary application builds and publishes also copy both files beside
the executable; portable ZIP/tar.gz archives retain them at the archive root.
Keep these files when repackaging or installing the build.

The third-party bundle records the restored application package versions, full
license/notice texts from their NuGet packages or upstream projects, retained
source/schema/asset notices, the Outfit font's SIL OFL and the bundled .NET
runtime notices. Current package licenses supersede historical descriptions of
older dependency versions, including SharpZipLib's former GPL description.
NuGet build-only reference assemblies and Avalonia.BuildServices are excluded.
Apache log4net's upstream `NOTICE` is included as well as its Apache-2.0 license;
the NuGet package omits that attribution file.

After changing dependencies or the bundled runtime, perform a locked restore
and refresh the checked-in bundle with
`python scripts/generate-third-party-notices.py`. This maintenance script uses
upstream network sources; normal builds and the About view do not need a network
connection. Review the resulting notices alongside the package change. The
generator reads package folders from each project's restore assets, including
configured global package caches. Fallback license sources for lzo.net,
MicroCom and Outfit use reviewed immutable commits.
The package verifier checks complete file contents, the packaged dependency names
and versions as exact recorded identities, and runtime coverage; stale or missing
notices fail acceptance. `python scripts/test-redistribution-notices.py` runs 13
fixtures, including nine rejected archives, version/name prefix rejection and
regeneration from a configured cache. Windows/Linux acceptance also runs them.

The Wise installer is not generated by the automated checks. Its installed
shared library still contains the notices shown by WinForms; an actual MSI
installation must verify that the dialog is reachable and retain the companion
notice files. This work addresses the repository's redistribution-notice
requirements and the pinned dependencies; it does not assert ownership of every
asset or grant trademark rights. Release signing is outside this batch, at the
user's request.
