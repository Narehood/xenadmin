The framework source confirms that `OnFormClosed` removes the form from
`Application.OpenForms` before notifying observers, and that `Application.Exit`
uses the modern closing callbacks. The review's exact loop description is not
accurate for .NET 10: it processes the last open form, and an escaping callback
exception can abort exit. This work establishes base cleanup despite earlier
failure; it does not claim to have reproduced an infinite exit loop.
Sources: [.NET 10 Form](https://github.com/dotnet/winforms/blob/v10.0.0/src/System.Windows.Forms/System/Windows/Forms/Form.cs),
[Application](https://github.com/dotnet/winforms/blob/v10.0.0/src/System.Windows.Forms/System/Windows/Forms/Application.cs).

## Limits

The fault fixtures seed in-process registries/OpenForms without loading the
inventory windows, deliberately dispose a synthetic HA wait handle without
starting its worker, and simulate registry failure. Focus policy uses a callback
to avoid desktop-dependent focus assertions. Unexpected cleanup exceptions still
propagate after base close processing. Real task cancellation, full application
shutdown, modal owner focus, UAC and live pool acceptance remain manual checks.
No disposable environments are available; the Debian reboot report is still
undiagnosed. No merge, release or live pool change is part of this review update.
