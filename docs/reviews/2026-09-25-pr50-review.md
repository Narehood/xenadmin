## Findings and dispositions

| Finding | Disposition |
| --- | --- |
| [Unsupported or mixed bond modes default to active-backup](https://github.com/Narehood/xenadmin/pull/50#discussion_r4109816458) | Already fixed by `7cb543d9c`. The editor shows the current raw mode/hash, leaves unsupported or mixed values unselected, and guards both Apply and its command until an explicit supported choice. Six regression cases cover unknown, missing/future hashing, mixed-host state, and unchanged supported mode. |
| [IPv4 None submits the old address](https://github.com/Narehood/xenadmin/pull/50#discussion_r4109816459) | Already fixed by `7cb543d9c`. The worker uses `PIF.async_reconfigure_ip` with the reviewed empty address/mask/gateway for None. Static/DHCP retain the shared action. Loopback RPC regressions cover empty arguments, preserved IPv6/DNS, stale identity rejection, cleanup and no repeated mutation after rejection. |
| [Basic/Digest selection appears to constrain all proxy traffic](https://github.com/Narehood/xenadmin/pull/50#discussion_r4109816461) | Valid UI-scope concern. The removed registration API was already ineffective on .NET 8, so the migration did not remove a working restriction. Both settings UIs now explain that this choice governs transfer tunnels and that other requests negotiate independently. See the runtime sources and reproducible proxy probe in the [migration record](../dotnet10-migration.md). |
| [Invert the management-IP disruption flag](https://github.com/Narehood/xenadmin/pull/50#discussion_r4109842685) | Suggested inversion rejected after tracing the flag's consumers. `ChangeNetworkingAction.Run` also uses `!managementIPChanged`. `XenConnection` uses this flag to tolerate event failures and keep retrying remembered endpoints. Replacing the management address requires a manual reconnect to its new address; it must not enable indefinite retries against the old one. The shell retains that behavior, with a code comment and four new IPv6 worker/RPC regression cases. |
| [Define partial-pool recovery](https://github.com/Narehood/xenadmin/pull/50#issuecomment-5842147595) | Valid documentation improvement. The [recovery procedure](../advanced-networking.md#recovering-an-interrupted-pool-operation) describes fresh server-state reads, a per-host record, separate mode/hash outcomes, uncertain failed responses, and guarded SR-IOV reconciliation. No automatic rollback or durable per-host journal is implemented. |
| Generic docstring-coverage warning | No bulk comment generation. Document the non-obvious reconnect semantics and recovery procedure; the coverage score alone does not identify a behavior defect or justify boilerplate across every touched function. |
| [Conflicting handoff validation totals](https://github.com/Narehood/xenadmin/pull/50#discussion_r4110000260) | Valid clarity improvement. The 524-test/32,239-resource run belongs to `7cb543d9c`; 528 tests/32,240 resources belong to `adcb021c4`. Both are now labeled by commit instead of changing historical evidence. Graph-editor validation is recorded separately. |

The new IPv6 regressions observe the actual worker's flag and interface lock at
the loopback RPC boundary for a primary management address change, a DNS-only
change, a secondary address-family change, and a non-management interface.
They verify the submitted IPv6/DNS values, preservation of cached IPv4/IPv6,
error propagation, released locks, and no repeated mutation after rejection.
They do not simulate a real pool disconnect or prove live reconnection behavior.

Local locked validation passed 528 shell tests in each of Release and Debug,
including 72 host-IP cases. The unchanged shared libraries passed 73 tests on
each of `net481` and `net10.0`. The 12 proxy challenge cases passed on .NET
10.0.12. The WinForms Release build and all 32,240 resources in 290 sets passed;
it reused existing RDP interop with `SkipRdpAxImp=true` on this machine. Actual
settings layouts were checked at three WinForms widths and two shell sizes.
Existing Windows ACL analyzer and legacy WinForms obsolete warnings remain.

No disposable pools or real update/migration/console test machines were available.
Live networking, pool-failure recovery, physical desktop, and UAC/update checks
remain the user's manual acceptance work; see [platform acceptance](../platform-acceptance.md).
